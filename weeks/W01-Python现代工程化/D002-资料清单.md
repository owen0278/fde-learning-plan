## 一、类型注解 / dataclass / pydantic / 泛型

这一块是**今天投入产出比最高的部分** —— 后面做 FastAPI、写 Agent、调 OpenAI SDK，
到处都是 pydantic model。看不懂类型注解，后面每一步都会卡。

### 切入点（英语弱就从这里开始）

> 为什么先读这个：它几乎全是代码对照，左边 Python 2/旧写法，右边现代注解写法，

### Pydantic（今天的重点）

| 内容 | 地址 |
| --- | --- |
| 官方文档首页 | <https://docs.pydantic.dev/latest/> |
| Models 核心概念 | <https://docs.pydantic.dev/latest/concepts/models/> |

**Pydantic 为什么重要**：它是 Python AI 工程的事实标准。
OpenAI SDK 的返回值、LangChain 的工具定义、FastAPI 的请求体，底层全是 pydantic。
今天至少要搞明白三件事：

1. `BaseModel` 怎么定义，字段怎么加校验
2. `model_dump()` / `model_validate()` 怎么在 dict 和对象之间转
3. 为什么它比 `dataclass` 更适合做数据边界（因为它会**强制校验类型**）

## 二、推导式 / 生成器 / context manager / 自定义异常

| 主题 | 地址 |
| --- | --- |
| 列表推导式（官方教程） | <https://docs.python.org/3/tutorial/datastructures.html> |
| 生成器与迭代器（官方 HOWTO） | <https://docs.python.org/3/howto/functional.html> |
| contextlib（with 语句底层） | <https://docs.python.org/3/library/contextlib.html> |
| 错误与异常（官方教程） | <https://docs.python.org/3/tutorial/errors.html> |

**优先级判断**（时间不够就按这个顺序取舍）：

1. **context manager** —— 写 AI 应用时管理资源（文件、数据库连接、LLM 客户端、临时目录）天天用，
   `@contextmanager` 装饰器必须会
2. **自定义异常** —— 后面写 Agent 的**重试与降级**逻辑全靠它，
   你得能区分「该重试的错误」和「该放弃的错误」
3. **生成器** —— 处理大文件、流式输出（LLM 的 stream 响应就是生成器）时绕不开
4. **推导式** —— 你会用，只是不熟，扫一眼就行
