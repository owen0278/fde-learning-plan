## 三、优先级判断：mock 是今天最该花时间的

三个概念里，**mock 的性价比最高**，理由是：

FDE 写测试时 90% 的难点不是"怎么测"，而是
**"这个外部依赖怎么假装"** —— 大模型 API 要花钱、数据库要连接、第三方服务不稳定。

`unittest.mock` 必须掌握的几种用法：

```python
# 1. 替换函数返回值
@mock.patch("mymodule.call_llm")
def test_x(mock_llm):
    mock_llm.return_value = "假的大模型回复"

# 2. 模拟抛异常（测重试逻辑）
mock_llm.side_effect = TimeoutError

# 3. 断言被调用了几次、传了什么参数
mock_llm.assert_called_once_with("prompt")
```

**第 2 条尤其重要** —— 后面写 Agent 的降级逻辑，
全靠 mock 出各种异常来验证"该重试还是该放弃"。

## 四、一个容易被忽略的视角

任务卡只说了"覆盖率 70% 以上"，但我想提醒一句：

**覆盖率是手段，不是目的。** 一个断言都没写的测试也能跑出 100% 覆盖率。

更有价值的问题是：**如果你的 API 被人乱传参数，会不会崩？**

今天给 CRUD API 补测试时，除了正常路径，务必覆盖：

- 金额为负数 → 应该被 Pydantic 拒绝（422）
- 必填字段缺失 → 422
- 查询一个不存在的 ID → 404
- 状态值传了枚举外的东西 → 422

**这批"边界测试"比覆盖率数字值钱得多**，
而且它和 W06 的 Eval 思维是同一件事：
你怎么证明这个东西真的能用？
