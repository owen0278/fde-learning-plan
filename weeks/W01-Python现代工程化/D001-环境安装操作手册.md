# D001 环境安装操作手册

> 对应任务：**安装 Python 3.12 + uv，配置 VS Code 或 Cursor，装好 Ruff / pyright / GitLens**
> 适用系统：Windows 10（你的机器版本 19045）
> 预计耗时：40–60 分钟（含下载）

---

## 重要：用哪个终端

**本文所有命令请在「PowerShell」或「命令提示符（CMD）」里执行，不要用 Git Bash。**

原因：winget 是 Windows 原生工具，在 Git Bash 里偶发交互异常。
打开方式：按 `Win` 键，输入 `PowerShell`，回车。

> 每一步装完后，都要**关掉终端重开一次**才能让新命令生效。手册里会明确提示你什么时候该重开。

## 第 0 步：确认起点

先把下面这段整块粘进 PowerShell，看看当前状态：

```powershell
python --version
uv --version
code --version
```

**你机器上的实测结果**（我已帮你探测过）：

| 命令 | 结果 | 说明 |
| --- | --- | --- |
| `python --version` | 提示找不到 | 系统里没有属于你的 Python |
| `uv --version` | 提示找不到 | 未安装 |
| `code --version` | 提示找不到 | VS Code 未安装 |
| `winget --version` | `v1.29.290` | ✅ 可用，后面的安装全靠它 |

三条都报"找不到"是正常的，说明是干净环境，不会有版本打架。开始装。

## 第 1 步：安装 Python 3.12

### 执行

```powershell
winget install --id Python.Python.3.12 -e --accept-package-agreements --accept-source-agreements
```

### 可能出现的提示

- 若弹出「是否同意安装」→ 输入 `Y` 回车
- 若提示需要管理员权限 → 右键 PowerShell 选「以管理员身份运行」再执行一次

### 验证

**关掉 PowerShell，重新打开**，然后：

```powershell
python --version
```

期望输出：

```
Python 3.12.x
```

### ⚠️ 两个必须处理的坑

**坑 1：输入 `python` 却弹出 Microsoft Store**

这是 Windows 的「应用执行别名」在捣乱。解决：

1. `Win` 键 → 输入 `管理应用执行别名` → 回车
2. 找到 `python.exe` 和 `python3.exe` 两项，**全部关掉开关**

关掉后重开终端，`python --version` 就正常了。

**坑 2：明明装了却还是找不到**

说明 PATH 没生效。最快办法是**注销再登录一次 Windows**，比重装省事。

### 为什么是 3.12 而不是更新的

Python 3.13 / 3.14 已经发布，但 AI 生态（PyTorch、部分向量库）对新版本的支持通常滞后 3–6 个月。
**3.12 是当前兼容性与新特性最平衡的版本**，也是多数 AI 公司的生产环境版本。学它不会错。

## 第 2 步：安装 uv

### 这是什么

uv 是 Rust 写的新一代 Python 包/环境管理器，比 pip 快 10–100 倍，一条命令顶过去的一堆。
2026 年新项目基本默认用它，面试时说你用 uv 是加分项。

**它替代的东西**：`pip` + `venv` + `pip-tools` + `pyenv`。

### 执行（推荐）

```powershell
winget install --id astral-sh.uv -e --accept-package-agreements --accept-source-agreements
```

### 备选方案（winget 装不上时用）

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

### 验证

**重开 PowerShell**：

```powershell
uv --version
```

期望输出类似：

```
uv 0.9.x
```

版本号是多少无所谓，能出版本号就成。

## 第 3 步：安装 VS Code

### VS Code 还是 Cursor

**我建议先装 VS Code。** 理由：

- 免费，不用考虑订阅
- 第一周的目标是**重建编码手感**，用不带 AI 补全的编辑器，逼自己真的动手敲。这一步偷懒，后面全是债
- 面试时的共享屏幕环境通常是 VS Code

等你到 W4 开始做 AI 项目了，再换 Cursor 不迟 —— 到时候你已经有了判断力，不会被 AI 牵着走。

如果你想直接上 Cursor，把下面的 `Microsoft.VisualStudioCode` 换成 `Anysphere.Cursor` 即可，其余步骤完全一样。

### 执行

```powershell
winget install --id Microsoft.VisualStudioCode -e --accept-package-agreements --accept-source-agreements
```

安装时如果看到这个选项，**勾上**：

- ✅ **添加到 PATH（Add to PATH）** —— 不勾的话后面 `code` 命令用不了
- ✅ 添加到「通过 Code 打开」的右键菜单（可选，但很方便）

### 验证

**重开 PowerShell**：

```powershell
code --version
```

期望输出三行，第一行是版本号。

## 第 4 步：安装扩展

### 方式 A：命令行（快）

```powershell
code --install-extension ms-python.python
code --install-extension ms-python.vscode-pylance
code --install-extension charliermarsh.ruff
code --install-extension eamodio.gitlens
```

### 方式 B：图形界面（稳）

如果上面的命令报错，就在 VS Code 里手动装：

按 `Ctrl + Shift + X` 打开扩展面板，依次搜索并安装：

| 扩展名 | 发布者 | 作用 |
| --- | --- | --- |
| **Python** | Microsoft | Python 语言支持、调试、解释器选择 |
| **Pylance** | Microsoft | 类型检查与智能提示，**底层就是 Pyright** |
| **Ruff** | Astral Software | 代码格式化 + 静态检查，替代 black/flake8/isort |
| **GitLens** | GitKraken | 看每一行代码是谁在什么时候改的 |

> 说明：Pyright 本身是命令行工具，在 VS Code 里以 **Pylance** 这个扩展的形式提供。装了 Pylance 就等于装了 pyright，不用另外装。

**装完重启一次 VS Code。**

### 可选但推荐

```powershell
code --install-extension tamasfe.even-better-toml
code --install-extension usernamehw.errorlens
```

- Even Better TOML：高亮 `pyproject.toml`（uv 项目天天要改这个文件）
- Error Lens：把报错直接显示在代码行尾，新手排查问题快很多

## 第 5 步：配置 VS Code

按 `Ctrl + Shift + P`，输入 `Preferences: Open User Settings (JSON)`，回车，
把下面这段粘进去（如果文件里已有内容，在大括号内追加，注意逗号）：

```json
{
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff",
    "editor.formatOnSave": true,
    "editor.codeActionsOnSave": {
      "source.fixAll.ruff": "explicit",
      "source.organizeImports.ruff": "explicit"
    }
  },
  "python.analysis.typeCheckingMode": "basic",
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/Scripts/python.exe",
  "files.autoSave": "onFocusChange"
}
```

这几行在做什么：

| 配置 | 效果 |
| --- | --- |
| `defaultFormatter: ruff` | 保存时自动用 Ruff 排版 |
| `codeActionsOnSave` | 保存时自动修小毛病、自动整理 import 顺序 |
| `typeCheckingMode: basic` | 开启 Pyright 类型检查，但不开「严格」模式（不然第一天就会被满屏红线劝退） |
| `defaultInterpreterPath` | 自动识别 uv 建的虚拟环境 |

这一步是检验前面装没装对，务必做。


此时目录结构应该是：

```
├── pyproject.toml
├── README.md
└── main.py
```

**打开 `pyproject.toml` 看一眼**，这就是现代 Python 项目的配置文件，取代了以前的 `requirements.txt`。
`uv init` 已经帮你把项目名、版本、依赖要求都写好了。

### 跑起来

```powershell
uv run python main.py
```

期望输出：

```
Hello from hello-fde!
```

> 第一次用 `uv run` 会自动下载并锁定 Python 3.12，稍慢，属正常。

### 验证 Ruff

```powershell
uv add --dev ruff
uv run ruff check .
```

期望输出：

```
All checks passed!
```

再试格式化：

```powershell
uv run ruff format --check .
```

### 验证 Pylance

在 VS Code 里打开这个项目（`code .`），打开 `main.py`，
在文件末尾加一行故意写错的代码：

```python
x: int = "这明显不是数字"
```

**如果行号左边出现波浪线**，说明 Pylance（Pyright）在工作了。看完删掉这行。

### 验证 GitLens

随便打开一个在 git 仓库里的文件，把光标放到某一行，
**如果行尾浮现出「谁在什么时候改的这行」**，说明 GitLens 生效了。

## 常见报错速查

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `python 不是内部或外部命令` | PATH 未生效 | 关掉终端重开；还不行就注销重登 |
| `python` 打开应用商店 | 应用执行别名 | 见第 1 步「坑 1」 |
| `uv 不是内部或外部命令` | PATH 未生效 | 重开终端 |
| `code 不是内部或外部命令` | 装 VS Code 时没勾 Add to PATH | 重跑安装包选 Modify，勾上 PATH |
| `uv` 下载超时 | 网络问题 | 见下方「国内加速」 |
| VS Code 里没有 Python 解释器可选 | 虚拟环境没被识别 | `Ctrl+Shift+P` → `Python: Select Interpreter` → 手动选 `.venv\Scripts\python.exe` |

### 国内加速（可选）

如果 uv 下包很慢，在 `pyproject.toml` 里加：

```toml
[tool.uv]
index-url = "https://pypi.tuna.tsinghua.edu.cn/simple"
```

常用的国内镜像：

- 清华：`https://pypi.tuna.tsinghua.edu.cn/simple`
- 阿里：`https://mirrors.aliyun.com/pypi/simple`
