## 五、优先级判断

任务卡列了四个命令。按「用得上的频率 + 搞砸的风险」排序：

1. **`stash`** —— 天天用。写到一半要切分支，先 `git stash`，回来 `git stash pop`
2. **`reflog`** —— 救命用。误操作后的最后一道防线，**必须知道它存在**
3. **`rebase`** —— 天天用但危险。记住一条铁律：**只 rebase 自己还没推的提交**
4. **`cherry-pick`** —— 偶尔用。从别的分支摘一个提交过来

⚠️ **唯一要背下来的安全规则**：
`git rebase` 只对你**本地未推送**的提交用。
已经 push 到公共分支的提交再 rebase，会改写历史、坑到协作者 ——
你现在是双笔记本同步，这条更要命。

## 六、今日产出：中英双语 README

任务卡要求写 README（含架构说明与启动命令）。
**这是你简历作品集的第一块门面，别糊弄。**

建议结构：

```markdown
# 项目名

一句话说明它解决什么问题

## 快速开始
（三条命令能跑起来）

## 架构说明
（一张手绘图或文字描述，说明数据怎么流）

## 技术选型与理由
（为什么用 FastAPI / 为什么用 pydantic）

## 已知限制
（诚实说明没做什么 —— 面试官很吃这一条）
```

写中文版，再写一份英文版（`README_EN.md`）。
英文版写不完美没关系，目标是练 —— 外企岗看的就是这个。
