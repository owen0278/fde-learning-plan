## 一、GitHub Actions

| 主题 | 地址 |
| --- | --- |
| Actions 官方文档 | <https://docs.github.com/en/actions> |
| 快速开始 | <https://docs.github.com/en/actions/quickstart> |
| **Python 构建与测试（照抄这篇）** | <https://docs.github.com/en/actions/automating-builds-and-tests/building-and-testing-python> |

第三个链接就是今天要的东西 —— 官方给的 Python 工作流模板，
改几行就能用：把 `pip install` 换成 `uv sync`，加上 ruff 和 pyright 两步。

### 今天的 CI 要跑什么

任务卡要求：push 时自动跑 `ruff` + `pyright` + `pytest`。
工作流文件放在 `.github/workflows/ci.yml`：

```yaml
name: CI
on: [push, pull_request]
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
      - run: uv sync --all-extras --dev
      - run: uv run ruff check .
      - run: uv run pyright
      - run: uv run pytest --cov
```

**注意用 `astral-sh/setup-uv`** —— 官方 action，速度快得不像话，
比配 Python + pip 缓存那一套省心得多。

## 二、pre-commit

| 主题 | 地址 |
| --- | --- |
| pre-commit 官方 | <https://pre-commit.com/> |
| 可用的 hooks 清单 | <https://pre-commit.com/hooks.html> |

配置思路：把 ruff 和 pyright 同时挂到 pre-commit 上，
**本地提交前就拦截脏代码**，不用等 CI 跑完才发现。

```yaml
# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.7
    hooks:
      - id: ruff-check
      - id: ruff-format
```

## 三、优先级判断

**CI 优先，pre-commit 其次。**

理由：CI 是"公开保证"—— 面试官点开你的仓库，
看到 Actions 那一栏一片绿，或看到一个绿色的 badge，
直接就说明"这人懂工程规范"。这是**可见的、能加分的东西**。

pre-commit 是给自己省时间，重要但不外显。时间不够就先把 CI 跑通。
